# Duplicate File Finder — Complete Engineering Plan

Confirmed defaults assumed: prefix hash = BLAKE3(first 16 KB ‖ last 4 KB); DB = WAL + `synchronous=NORMAL`, **commit** every 50k rows or 5 s, **checkpoint** (PASSIVE) when WAL exceeds a page threshold, TRUNCATE only at shutdown. Override any of these at any time — they're isolated behind one config struct.

---

## 0. Guiding principles  — ⚪ applied

1. **API-first, CLI-thin, TUI-later.** All logic in `core`; `cli` and `tui` are just consumers.
2. **Safe core, unsafe shell.** No `#[cfg(target_os)]` in `core`; `core` declares `#![forbid(unsafe_code)]`. All FFI/`unsafe` and all per-OS logic (path encoding, volume identity, storage-profile detection, extents) lives in `backend-*` crates behind safe traits (`Enumerator`, `ContentReader`, `VolumeIdentity`, `StorageProbe`). `core` only consumes those traits.
3. **IO-bound, not CPU-bound.** Every design choice optimizes for disk seek/throughput, not hash cycles. BLAKE3 is not the bottleneck; the scheduler is.
4. **Progressive narrowing.** Each pass shrinks the working set. Never do full reads until size + prefix have already cut candidates.
5. **Resumable by construction.** Every file has a persisted state. Kill -9 and restart must lose at most one batch window.
6. **Honest reporting.** Reflinks/hardlinks/clones labeled distinctly; "wasted space" is truthful or marked unknown.
7. **Correctness gate.** No deletion without `--dry-run` off + explicit action command. v1 ships scan/report/lookup only.

## 4. Phase 1 — DB, resume, lookup, state machine (EMPHASIS)  — 🟡 partial

This is the phase that determines whether the tool is a toy or a product. Everything after it depends on the invariants established here.

### 4.1 Objectives  — ✅ done

1. Persist enough state that a scan can be killed at any point and resumed to an identical result.
2. Persist enough identity that a rescan can skip unchanged files and detect moves.
3. Enable `lookup` — "does this new file duplicate anything in the index?"
4. Enable `report` — read-only queries over a completed DB.
5. Establish the schema-versioning discipline that every later phase builds on.
6. Establish the batched writer thread that decouples hash workers from disk sync cost.

### 4.2 Non-goals  — ✅ done

- No incremental *watch* mode (still one-shot scans; resume is manual).
- No action/delete/hardlink commands (Phase 7+ / post-MVP).
- No schema changes for reflink labels yet — but the schema must *anticipate* them (attributes bitfield, `sharing_id` column nullable).
- No cross-volume dedupe logic. Each volume indexed independently; a later phase can join across volumes by `(size, full_hash)`.

### 4.3 Data model (final v1 schema)  — ✅ done

```sql

-- PRAGMA foreign_keys = ON is set per-connection in Db::open (it is not persisted by SQLite).

-- rows: 'created_at', 'tool_version', 'hash_algo',

  last_seen_run_id INTEGER,

  file_id       BLOB,                    -- NTFS FRN (incl. sequence no.) | inode | APFS file id. NOT unique: hardlinks share it
  nlink         INTEGER NOT NULL DEFAULT 1,

  UNIQUE(volume_id, folder_id, name)

CREATE INDEX idx_files_full          ON files(full_hash)              WHERE full_hash IS NOT NULL;  -- volume-agnostic: lookup spans volumes
CREATE INDEX idx_files_state         ON files(volume_id, state);
CREATE INDEX idx_files_folder        ON files(folder_id);
CREATE INDEX idx_files_fileid        ON files(volume_id, file_id)     WHERE file_id IS NOT NULL;   -- non-unique
CREATE INDEX idx_files_seen          ON files(volume_id, last_seen_run_id);

);

CREATE TABLE run_volumes (

  FOREIGN KEY (run_id, volume_id) REFERENCES run_volumes(run_id, volume_id)

CREATE TABLE errors (
  id            INTEGER PRIMARY KEY,
  run_id        INTEGER NOT NULL REFERENCES scan_runs(id),
  file_row_id   INTEGER,                 -- files.id (rowid), NOT files.file_id
  path          BLOB,
  kind          INTEGER NOT NULL,        -- permission | io | too_long | changed_during_read | other
  message       TEXT

```

**Design decisions baked in:**

- **Path stored as (folder_id, name)**, not a full path string. Rationale: folder overlap queries (your #19) become a cheap `GROUP BY folder_id`; rename of a folder is one row; Unicode components stored once. Full path reconstructed via recursive CTE or materialized in a view `v_files` for the report.
- **`file_id` is indexed but NOT unique.** Hardlinks share one inode/FRN, so a UNIQUE constraint would reject the second link. The non-unique index still enables move detection on rescan (see 4.7a) and hardlink collapsing before hashing (see 4.4a).
- **Root folder uses `parent_id = 0`**, never NULL, so `UNIQUE(volume_id, parent_id, name)` actually holds for roots.
- **`last_seen_run_id`** marks rows not seen by the latest completed enumeration as stale; report and lookup exclude them.
- **`state` machine** (see 4.4) is the resume backbone.
- **`prefix_bytes`** stores exactly what the prefix hash covered. If a future version changes prefix strategy (e.g., 8 KB → 16 KB), old rows are invalidated automatically by comparing to current config.
- **`attrs` bitfield** reserves room for reflink/hardlink/sparse labels in Phase 4 without a migration.
- **`hash_algo` in `meta`** invalidates the whole DB if the user changes `--hash`. Refuse to reuse unless `--force` (then wipe hash columns).
- **`PRAGMA user_version`** is the only schema-version source; `meta` does not duplicate it.

### 4.4 File state machine  — ✅ done

```
 0  ENUMERATED     metadata only, hashes null
 1  SIZE_CANDIDATE has >= 1 other live file (distinct inode) with the same size
 2  PREFIX_HASHED  prefix_hash set, has a prefix partner
 3  FULL_HASHED    full_hash set
 4  VERIFIED       byte-compared (only with --verify=byte; verify lands in Phase 2 alongside the scheduler)
 5  DONE           terminal success for hashed files
-1  SKIPPED        zero-length, excluded by filter, symlink, non-regular, cloud placeholder
-2  ERROR          err column holds reason
-3  UNIQUE_SIZE    terminal: no size partner at scan time (no hashes stored)
-4  UNIQUE_PREFIX  terminal: size partner existed but no prefix partner (prefix_hash stored)
```

Transitions move forward only within a run. Terminal states (5, -1..-4) are never revisited in the same run; a rescan may reset a row to 0 (see 4.7a).

Rules:
- A file enters pass P only if its state is the state P consumes (`pass_size`: 0, `pass_prefix`: 1, `pass_full`: 2, `pass_verify`: 3).
- **Exception (HDD merged pass, Phase 2):** a merged prefix+full pass may move 1 → 3 directly, writing both hashes in one `Batch::Hashed`.
- Without `--verify`, `pass_full` writes state 5 directly after the full hash (3 is transient). With `--verify=byte`, 3 → 4 → 5.
- Batches update state in a single SQL transaction per batch.
- Report considers `state IN (3, 4, 5) AND last_seen_run_id = <latest completed run for volume>`.
- Lookup considers every live row with `state NOT IN (-1, -2)` (see 4.8).

### 4.4a File eligibility and hashing rules  — 🟡 partial

Applied in `pass_enumerate` / `pass_*`, identical in every backend:

1. **Regular files only.** Directories recurse; symlinks, FIFOs, sockets, char/block devices → `SKIPPED`. Never `open()` a non-regular file — reading a FIFO blocks forever.
2. **Cloud placeholders skipped by default.** Windows `FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS` / `RECALL_ON_OPEN` / `OFFLINE`, macOS `SF_DATALESS`: reading triggers a download. → `SKIPPED` with `attrs.placeholder`. Opt-in via `--include-placeholders`.
3. **Hardlink collapse.** Before `pass_prefix`, group candidates by `(volume_id, file_id)`. Hash one representative per inode, copy its hashes to the siblings. Size partners count distinct inodes, not paths: two links to one inode alone are not a duplicate. **`attrs.hardlink` is set at enumeration** (whenever `nlink > 1`), not here, so hardlink-only pairs that become `UNIQUE_SIZE` are still flagged. Generic backend gets `file_id`/`nlink` from `std::os::unix::fs::MetadataExt` on Unix; on Windows it's `None` until Phase 3 (no hardlink collapse there in Phase 0–2; documented limitation).
4. **Small-file prefix rule.** Let `F = prefix_first_bytes` (16 KiB), `L = prefix_last_bytes` (4 KiB). If `size <= F + L`, the prefix covers the whole file: `prefix_hash = full_hash = BLAKE3-128(entire file)`, `prefix_bytes = size`, and the file skips `pass_full`. Otherwise prefix = `BLAKE3-128(bytes[0..F] ‖ bytes[size-L..size])`. No overlap is possible in the large-file branch.
5. **Change-during-read guard.** Re-`stat` after hashing (size + mtime_ns + ctime_ns where available). If anything changed → `ERROR(changed_during_read)`; the next resume/rescan retries it. Never persist a hash for a file that changed under the reader.

### 4.4b Pipeline phases (`run_volumes.phase_reached`)  — ✅ done

`phase_reached` = the last phase **fully committed** for that `(run, volume)`. Stored as `Phase as i64`.

```rust
// core::model
#[repr(u8)]
#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord)]
pub enum Phase {
    None       = 0, // run started, nothing committed
    Enumerated = 1, // pass_enumerate done (incl. rescan merge + stale deletion, 4.7a)
    SizeDone   = 2, // pass_size done: every live row is 1, -1, -2 or -3
    PrefixDone = 3, // pass_prefix done: no row left at 1
    FullDone   = 4, // pass_full done: no row left at 2
    Verified   = 5, // pass_verify done (Phase 2+; skipped when --verify is off)
    GroupsDone = 6, // dup_groups recomputed for this volume; terminal
}
```

Resume starts at the pass **after** `phase_reached`. `--stop-after-pass N` (test hook) stops right after committing `PhaseComplete { phase: N }`.

### 4.5 Batched writer thread  — 🟡 partial

**Shape:** a `std::sync::mpsc::sync_channel::<Batch>(N)` (bounded, N ≈ 4). Hash workers send `Batch` structs. One writer thread owns the `rusqlite::Connection`, drains the channel, runs transactions.

**Row IDs are pre-assigned.** The pipeline needs `files.id` immediately (to send `SizeCandidate(Vec<i64>)` etc.), but the writer commits asynchronously. So `core::db::IdAllocator` hands out IDs from an `AtomicI64` seeded with `MAX(id)+1` (files and folders separately) at run start. Enumeration inserts with explicit `id`. On a rescan, an existing row keeps its old ID — the enumerator looks it up by `(volume_id, folder_id, name)` via a read-only connection, or via `file_id` for move detection.

```rust
pub enum Batch {
    Folders(Vec<FolderRow>),                   // upsert folders (explicit id)
    Enumerated(Vec<FileEntry>),                // UPSERT on (volume_id, folder_id, name); state=0, last_seen_run_id=run
    SizeCandidate(Vec<i64>),                   // state 0 -> 1
    UniqueSize(Vec<i64>),                      // state 0 -> -3
    PrefixHashed(Vec<(i64, Hash)>),            // set prefix_hash, state 1 -> 2
    UniquePrefix(Vec<(i64, Hash)>),            // set prefix_hash, state 1 -> -4
    Hashed(Vec<(i64, Hash, Hash)>),            // prefix+full in one go (small files; HDD merged pass from Phase 2): 1 -> 5. Phase 2+: 1 -> 3 when --verify
    FullHashed(Vec<(i64, Hash)>),              // set full_hash, state 2 -> 5. Phase 2+: 2 -> 3 when --verify
    Verified(Vec<i64>),                        // Phase 2+ only: state 3 -> 5. Defined now so the enum is stable; unused in Phase 1
    Error(Vec<ErrRow>),                        // state -> -2, err set, errors row inserted
    PhaseComplete { run_id: i64, volume_id: i64, phase: Phase }, // see 4.4b; written in the SAME txn as the preceding rows
    Checkpoint,                                // request PASSIVE WAL checkpoint
    Shutdown,
}
```

Writer responsibilities:
1. On open, in this order: `busy_timeout = 5000` (first, because switching to WAL needs a lock), then `journal_mode = WAL`, **checking the returned mode**, then `synchronous = NORMAL`, `foreign_keys = ON`, `temp_store = MEMORY` and `wal_autocheckpoint = 10000`. SQLite silently keeps the old mode on filesystems that can't do WAL (e.g. network mounts). If the returned mode isn't `wal`, fail with `CoreError::WalUnavailable` and tell the user to put `--db` on a local disk.
2. Accumulate rows until `BATCH_ROWS = 50_000` or `BATCH_MS = 5000`, then commit. `PhaseComplete` forces a commit that includes all rows received before it, so `phase_reached` never leads the data.
3. All writes are idempotent: `Enumerated` uses `INSERT ... ON CONFLICT(volume_id, folder_id, name) DO UPDATE`; all state changes are `UPDATE ... WHERE id = ?`. Replaying a lost batch is safe.
4. Checkpointing: set `PRAGMA wal_autocheckpoint = 10000` (pages) on open. SQLite then runs a PASSIVE checkpoint automatically on commit once the WAL passes that size. PASSIVE never blocks readers (`report`/`lookup` may run concurrently). `Batch::Checkpoint` forces an explicit `wal_checkpoint(PASSIVE)`.
5. On `Shutdown`: drain, commit, `wal_checkpoint(TRUNCATE)`, close.
6. On writer panic or SQLite error: the channel closes, senders get `SendError`, the pipeline sets the cancel token and returns `CoreError::WriterDied`. Committed batches are intact; the uncommitted window is redone on resume.

**Durability note:** a process kill (kill -9) never loses committed txns in any journal mode. WAL is required for throughput and for concurrent readers, not for kill safety. On power loss, the last few commits may roll back, but the DB stays consistent. Resume handles both.

**Why a single writer:** SQLite permits one writer. Splitting writes across threads forces serialization at the SQLite level and adds contention. One writer + batched transactions saturates WAL throughput on both HDD and SSD.

**Throughput budget:** with 50k-row transactions, expect ≥ 200k row-writes/sec on NVMe, ≥ 30k/sec on HDD. At 10 M files × ~3 writes per file (enumerate + size + hash), that's ~2.5 min of DB time on NVMe and ~17 min on HDD. HDD is the concern: the DB and the scanned data compete for the same spindle if the DB lives on the scanned disk. Recommend `--db` on a different device for HDD scans; warn when the DB volume equals a scanned HDD volume. All of this runs concurrently with hashing.

### 4.6 In-memory working set  — 🟡 partial

Enumeration is streamed: `FileEntry`s go to the writer in batches and are not kept in a `Vec`. The only enumeration-time map is `dir_ids: HashMap<RawPath, i64>` (directory → folder id), which is bounded by directory count, not file count.

Size grouping does **not** use an in-memory map. After `PhaseComplete(enumerate)` is committed, `pass_size` runs one indexed query on a read-only connection:

```sql
SELECT size FROM files
WHERE volume_id = ?1 AND state = 0 AND last_seen_run_id = ?2
GROUP BY size
HAVING COUNT(DISTINCT COALESCE(file_id, id)) > 1;   -- distinct inodes, so hardlink pairs alone don't qualify
```

Rows of those sizes → `SizeCandidate`; all other state-0 rows → `UniqueSize`.

Two in-memory maps remain:

1. **`prefix_map: HashMap<Hash, SmallVec<[i64; 2]>>`** — built during `pass_prefix` from size candidates only (typically <20% of files). About 50 B/entry with hashbrown overhead, so 2 M candidates ≈ 100 MB.
2. **`full_map: HashMap<Hash, SmallVec<[i64; 2]>>`** — built only from prefix survivors (typically <5% of files). Small.

**Budget:** peak RSS target < 1.5 GB for 10 M files. `--mem-budget` defaults to **1 GiB** for the maps, which keeps the 1.5 GB target with headroom for buffers and SQLite cache.

Rationale for keeping these two maps in RAM: the pipeline consults them once per file per phase, and round-tripping to SQLite would add millions of point queries. The DB is for *persistence and resume*, not for the hot path.

**Rule:** if a map would exceed `--mem-budget`, switch that phase to "DB-backed mode": stream the partner lookup through `idx_files_prefix` / `idx_files_full` with `ORDER BY` + grouping cursor. This is slower but bounded. Log the switch at `warn`.

### 4.7 Resume protocol  — ✅ done

On `scan --resume`:
1. Open DB. Verify `meta.hash_algo` and the prefix config match the current config. If not, abort unless `--force`, which wipes the hash columns and resets those rows to state 0.
2. Load the latest `scan_runs` row with `status = 'running'`. None → error "nothing to resume". For each of its `run_volumes`, ask the backend `VolumeIdentity` for the UUID at that volume's roots (from `run_roots`). A mismatch aborts unless `--force`. If the UUID matches but the mount path moved, update `volumes.mount` and continue.
3. Per volume, `phase_reached` (4.4b) tells us where to resume:
   - `Phase::None`: enumeration incomplete. Re-enumerate all roots. Upserts make this idempotent, and it's cheap relative to hashing.
   - `Phase::Enumerated` or later: skip enumeration and start at the next pass.
   - `Phase::GroupsDone`: nothing to do for this volume.
4. For each remaining phase, select exactly the rows in that pass's input state (see 4.4) with `last_seen_run_id = run`. Rebuild `prefix_map` / `full_map` from rows already past that pass. Example for `pass_prefix`: load `(prefix_hash, id)` where `state IN (2, -4)`, then process rows where `state = 1`.
5. Recompute `dup_groups` for the volume at the end. This is idempotent: `DELETE FROM dup_groups WHERE volume_id = ?`, then `INSERT ... SELECT` grouped by `full_hash` with `distinct_inodes > 1`.
6. Set `scan_runs.finished_at` and `status = 'finished'`.

**Abandoned runs:** a fresh `scan` (no `--resume`) first sets `status = 'abandoned'` on every `running` row that shares a volume with the new run, logging each at `warn`. It then starts its own run. Abandoned runs are never resumed. Their rows are reconciled by the new run's rescan merge (4.7a).

**Invariant:** running `scan --resume` on a completed DB is a no-op except for the `dup_groups` recompute.

**Crash mid-batch:** the DB has the pre-batch state. Resume redoes that batch. Idempotent because enumeration is an upsert and every state change is `UPDATE ... WHERE id = ?`.

**Crash mid-full-hash of one file:** state stays at 2, and the file is re-hashed on resume. Acceptable.

### 4.7a Rescan protocol (new run over an already-indexed volume)  — 🟡 partial

`scan` without `--resume` on a DB that already holds the volume starts a new `scan_runs` row. Unchanged files keep their hashes.

1. **Enumerate.** For each entry, look up the existing row by `(volume_id, folder_id, name)`.
   - Found, and `(size, mtime_ns, ctime_ns, file_id)` unchanged → keep `prefix_hash` / `full_hash`, reset `state = 0`, bump `last_seen_run_id`.
   - Found but changed → null both hashes, `state = 0`, bump `last_seen_run_id`.
   - Not found by path → try `(volume_id, file_id)` among rows **not yet seen this run**. A match counts as a **move** only if `size` and `mtime_ns` also match (guards against inode reuse after delete). On a move, update `folder_id` / `name` and keep the hashes. Otherwise insert a new row.
   - FAT/exFAT and any `file_id = NULL` rows: no move detection (no stable IDs). They fall through to insert.
2. **Stale rows.** After `PhaseComplete(enumerate)`, delete rows with `last_seen_run_id < run` **whose folder is inside one of this run's roots** (recursive CTE over `folders`). Rows under roots not scanned this run are left untouched. Do the same for orphaned `folders`.
3. **Re-group.** Run the passes as normal. Because every row is back at state 0, previously unique files can gain partners. Each pass **reuses a stored hash** when present and `prefix_bytes` matches config, so it does no I/O for unchanged files.

### 4.8 Lookup (check a new file post-scan)  — ✅ done

```rust
pub fn lookup(db: &Connection, reader: &dyn ContentReader, path: &Path, cfg: &Config) -> Result<LookupOutcome>;

pub enum LookupOutcome {
    Skipped(SkipReason),         // zero-length, non-regular, placeholder
    NoMatch,
    Matches(Vec<MatchRow>),
}

pub struct MatchRow {
    pub volume_id: i64,
    pub path: RawPath,
    pub freshness: Freshness,    // Fresh | Stale (size/mtime differ from DB) | Missing | Unmounted
}
```

Algorithm:
1. `stat` the path. Non-regular or placeholder → `Skipped`. `size == 0` → `Skipped`.
2. Candidates = live rows with the same `size` and `state NOT IN (-1, -2)` in **every** volume (one indexed query per volume via `idx_files_size`). Excluding them would make singletons from the scan invisible. Empty → `NoMatch` (fast path, no reads).
3. Compute the query file's prefix hash, using the small-file rule from 4.4a.
4. **Candidates without a stored `prefix_hash`** (state -3 `UNIQUE_SIZE`): if their volume is mounted, hash them on demand from disk. Otherwise keep them as `Unmounted` candidates that can't be confirmed.
5. Keep only candidates whose prefix equals the query's. None → `NoMatch`.
6. Compute the query's full hash. Hash on demand any surviving candidate without `full_hash` (state -4), with the same mounted/unmounted rule.
7. Keep candidates whose `full_hash` matches. Before returning each one, re-`stat` its path and set `freshness`. Never report a `Missing` file as a plain match.
8. Return `Matches` or `NoMatch`.

CLI: `dupfind lookup --db PATH FILE [--format json] [--insert]`.

**Read-only by default.** Hashes computed on demand are discarded. `--insert` opens a writer and persists them, plus the query file as a new row if it lives on an indexed volume.

**I/O budget:** the query file is opened at most twice (prefix, then full). Each candidate that needs on-demand hashing costs one more open. The typical case after a full scan, where the candidate already has hashes, adds 0 extra opens. Benchmark a 10 GB file against a 10 M-row DB on NVMe; target < 5 s wall when candidates are pre-hashed.

### 4.9 Path storage and Unicode  — ✅ done

Decision: every name and path column is a **`BLOB` of raw bytes** (`folders.name`, `files.name`, `volumes.mount`, `errors.path`). Nothing is lossily converted on the way in.

- **Linux:** paths are bytes. Store as-is. Display via `from_utf8_lossy`.
- **Windows:** paths are UTF-16, possibly with unpaired surrogates. `backend-windows` encodes `OsStrExt::encode_wide()` output to **WTF-8** with its own small encoder/decoder. Do **not** persist `OsStr::as_encoded_bytes()`: std documents that encoding as unspecified and not for storage.
- **macOS:** HFS+ stores names in (a variant of) NFD. APFS **preserves** whatever normalization the creator used and compares normalization-insensitively. Either way, store the bytes as returned by the OS and never normalize on write.
- **Display:** `RawPath::to_display()` = lossy UTF-8 decode, then NFC (`unicode-normalization` crate). This is the same code on every OS, so `core` needs no `cfg`.

Implementation: `core::path::RawPath(Vec<u8>)`, holding bytes only. Conversion to and from native `OsString` lives in each backend (`trait PathCodec { fn to_raw(&OsStr) -> RawPath; fn to_native(&RawPath) -> OsString; }`). `backend-generic` implements it with `OsStrExt::as_bytes` on Unix and the WTF-8 codec on Windows.

Migration note: because we're doing this from day one, no migration is needed. Doing it later would be painful.

**Comparison rule:** paths are compared within a volume, byte-for-byte. Cross-volume comparison for duplicates uses hashes, never paths.

### 4.10 Volume identity and scan roots  — 🟡 partial

Volume identity is per-OS FFI, so it lives behind a backend trait and must ship **in Phase 1**: the resume guard depends on it. It goes in `backend-generic/src/volume.rs` under `cfg` (backends may use `cfg` and `unsafe`; `core` may not). Phases 3, 5 and 6 can override it later.

```rust
// core::traits
pub trait VolumeIdentity: Send + Sync {
    /// Identify the volume containing `path`.
    fn identify(&self, path: &Path) -> Result<VolumeInfo, CoreError>;
}

pub struct VolumeInfo {
    pub uuid: String,
    pub uuid_kind: UuidKind,   // FsUuid | VolumeSerial | FsidFallback | None
    pub mount: RawPath,
    pub fs_type: FsType,
    pub label: Option<String>,
}
```

- **Windows:** `GetVolumePathNameW` → `GetVolumeNameForVolumeMountPointW` → `\\?\Volume{GUID}\`. The GUID is the identity (`FsUuid`). It stays stable across reboots and drive-letter changes. Store the `GetVolumeInformationW` serial as a secondary check. Do **not** use `IOCTL_STORAGE_GET_DEVICE_NUMBER`: device numbers change across reboots and USB ports.
- **Linux:** map `st_dev` (major:minor) to the block device, then resolve its filesystem UUID through the `/dev/disk/by-uuid/*` symlinks (`FsUuid`). If no UUID exists (tmpfs, overlayfs, some network FSs), fall back to `statfs.f_fsid` (`FsidFallback`). That ID isn't guaranteed stable across reboots, so log a warning.
- **macOS:** `getattrlist` with `ATTR_VOL_UUID` (`FsUuid`). Fallback: `statfs.f_fsid` (`FsidFallback`).
- **`UuidKind::None`** (e.g. some SMB/NFS mounts): synthesize `"none:<fs_type>:<mount>"`. The resume guard is weak there; print a warning.

Stored in `volumes.uuid` / `uuid_kind`. On resume or rescan, a UUID mismatch at a recorded root → refuse unless `--force`. If the UUID matches but the mount moved, update `volumes.mount`.

**Scan roots:**
1. Canonicalize every `<ROOT>`. Drop roots nested inside another root.
2. Identify each root's volume. Group roots by volume. Write one `run_volumes` row per volume and one `run_roots` row per root.
3. **`--one-file-system` is the default:** the walker doesn't descend into a different `st_dev` (Unix) or a mounted-folder reparse point (Windows). With `--cross-mounts`, each crossed mount is identified and gets its own `run_volumes` row.
4. If the same volume UUID shows up at two different mounts (bind mounts), warn. The `(volume_id, file_id)` hardlink collapse (4.4a) keeps those files from being reported as duplicates.

### 4.12 Test plan for Phase 1  — 🟡 partial

**Unit tests (in `core`):**
- Schema apply + idempotent re-apply; refuse a DB with `user_version > EXPECTED_VERSION`.
- Every query helper against a fixture DB.
- State transitions legal/illegal (including the 1 → 5 merged-pass exception).
- Writer: batches flush on threshold, on `PhaseComplete` and on `Shutdown`. `phase_reached` is never committed ahead of its rows.
- Writer replay: apply the same `Enumerated` batch twice → identical DB.
- `Db::open` on a DB where WAL can't be enabled → `WalUnavailable`. Simulate with a test-only `journal_mode` override or a `:memory:` DB, which reports `memory`.
- Fresh scan with a `running` run on the same volume marks it `abandoned`; `--resume` then reports nothing to resume.
- Hardlink-only pair → `UNIQUE_SIZE` with `attrs.hardlink` set.
- `IdAllocator` seeded correctly on an existing DB.
- Volume UUID mismatch → refuse. Use a fake `VolumeIdentity` test double; a second real volume is not needed.
- Hash algo / prefix config mismatch → refuse unless `--force`.
- Path reconstruction from (folder_id, name) — recursive CTE correctness, including the root sentinel `parent_id = 0`.
- Unicode: NFD name stored byte-exact, NFC on display, byte-exact round-trip through the DB. Windows: unpaired-surrogate name round-trips through WTF-8.
- Small-file rule boundaries: size 1, `F+L`, `F+L+1`.

**Integration tests (`tests/`):**
- **End-to-end resume:** build a fixture tree (10k files, known dups). Run scan with `--stop-after-pass=N` for each N. Resume. Assert the final **normalized** groups equal a full uninterrupted scan. Normalized means a sorted set of `(full_hash, sorted member paths)`, ignoring `id` and `computed_at`.
- **Kill -9 test:** spawn the CLI as a subprocess and kill it mid-scan (`SIGKILL` on Unix, `TerminateProcess` on Windows). Restart with `--resume` and assert normalized convergence. Run 20 times at random kill points.
- **Lookup — basic:** scan, copy a scanned file elsewhere, lookup → match. Mutate one byte, lookup → no match.
- **Lookup — singleton regression:** a file with a unique size at scan time (state -3) is copied after the scan. Lookup of the copy **must** match. This guards the on-demand hashing path.
- **Lookup — freshness:** delete a matched file after the scan → reported `Missing`, not a plain match.
- **Hardlinks (Unix):** two links to one inode and nothing else → no group. Links plus an independent copy → one group with `distinct_inodes = 2` and `wasted_logical = size`.
- **Non-regular (Unix):** a FIFO and a socket in the fixture → `SKIPPED`, and the scan finishes (test timeout 30 s).
- **Change during read:** a `ContentReader` test double reports different metadata after the read → `ERROR(changed_during_read)` and no hash stored.
- **Rescan:**
  - An unchanged file is not re-read (instrumented reader counts opens = 0).
  - A modified file is re-hashed.
  - A deleted file's row is removed.
  - Rescanning only root A leaves root B's rows untouched.
- **Move detection:** rename a folder between scans and rescan. Assert the same `files.id` rows, the hashes kept, and zero bytes read for the moved files.
- **Volume guard:** run a scan with a fake `VolumeIdentity`, then rescan the same root with a fake that returns a different UUID → refusal. Then retry with `--force` → it proceeds.

**Property tests (`proptest`):**
- Round-trip: `FileEntry -> DB -> FileEntry` preserves all fields, including raw bytes in names. Name strategy:
  - Unix: any bytes except NUL and `/` (no OS allows those in a component); weight toward invalid UTF-8.
  - Windows: any `u16` sequence except NUL and `\ / : * ? " < > |`, including unpaired surrogates, encoded via the WTF-8 codec.
  - Plus NFC/NFD pairs of the same visible name.
- State machine: no sequence of valid transitions reaches an invalid state.

**Bench (Phase 1 scope):**
- 1 M-file synthetic DB: insert throughput, resume time, lookup latency at P50/P99.

```rust
use std::borrow::Cow;
use unicode_normalization::UnicodeNormalization;

/// Raw, lossless path bytes. Linux: native bytes. Windows: WTF-8. macOS: bytes as returned by the OS.
/// Never normalized on write. Conversion to/from OsStr lives in backend `PathCodec` impls.
#[derive(Clone, Debug, PartialEq, Eq, Hash, PartialOrd, Ord)]
pub struct RawPath(pub Vec<u8>);

impl RawPath {
    pub fn as_bytes(&self) -> &[u8] { &self.0 }

    /// Lossy, NFC-normalized string for display only. Never feed back into the DB.
    pub fn to_display(&self) -> String {
        let lossy: Cow<'_, str> = String::from_utf8_lossy(&self.0);
        lossy.nfc().collect()
    }
}
```

**`core/src/db/mod.rs`**

```rust
use rusqlite::{Connection, OpenFlags};
use std::path::Path;
use crate::{config::Config, error::CoreError};

pub mod ids;
pub mod queries;
pub mod schema;
pub mod writer;

pub const WAL_AUTOCHECKPOINT_PAGES: i64 = 10_000;

pub struct Db { pub conn: Connection }

impl Db {
    pub fn open(path: &Path, cfg: &Config) -> Result<Self, CoreError> {
        let conn = Connection::open(path)?;
        apply_pragmas(&conn, cfg)?;
        schema::apply_migrations(&conn)?;
        Ok(Self { conn })
    }

    pub fn open_readonly(path: &Path) -> Result<Self, CoreError> {
        let conn = Connection::open_with_flags(path, OpenFlags::SQLITE_OPEN_READ_ONLY | OpenFlags::SQLITE_OPEN_NO_MUTEX)?;
        conn.pragma_update(None, "foreign_keys", "ON")?;
        schema::check_version(&conn)?;
        Ok(Self { conn })
    }
}

fn apply_pragmas(conn: &Connection, _cfg: &Config) -> Result<(), CoreError> {
    conn.busy_timeout(std::time::Duration::from_secs(5))?;   // first: the WAL switch needs a lock
    // journal_mode returns the resulting mode; SQLite keeps the old mode silently if WAL is unsupported.
    let mode: String = conn.pragma_update_and_check(None, "journal_mode", "WAL", |r| r.get(0))?;
    if !mode.eq_ignore_ascii_case("wal") {
        return Err(CoreError::WalUnavailable { got: mode });
    }
    conn.pragma_update(None, "synchronous", "NORMAL")?;
    conn.pragma_update(None, "foreign_keys", "ON")?;
    conn.pragma_update(None, "temp_store", "MEMORY")?;
    conn.pragma_update(None, "wal_autocheckpoint", WAL_AUTOCHECKPOINT_PAGES)?;
    Ok(())
}
```

**`core/src/db/schema.rs`**

```rust
use rusqlite::Connection;
use crate::error::CoreError;

pub const EXPECTED_VERSION: i64 = 1;
const V1: &str = include_str!("schema/v1.sql");

pub fn current_version(conn: &Connection) -> Result<i64, CoreError> {
    Ok(conn.query_row("PRAGMA user_version", [], |r| r.get(0))?)
}

pub fn check_version(conn: &Connection) -> Result<(), CoreError> {
    match current_version(conn)? {
        v if v == EXPECTED_VERSION => Ok(()),
        v => Err(CoreError::SchemaVersion { found: v, expected: EXPECTED_VERSION }),
    }
}

pub fn apply_migrations(conn: &Connection) -> Result<(), CoreError> {
    let v = current_version(conn)?;
    if v > EXPECTED_VERSION {
        return Err(CoreError::SchemaVersion { found: v, expected: EXPECTED_VERSION });
    }
    if v == 0 {
        let tx = conn.unchecked_transaction()?;
        tx.execute_batch(V1)?;
        tx.pragma_update(None, "user_version", 1)?;
        tx.commit()?;
    }
    // future: if v == 1 { apply v2 } ...
    Ok(())
}
```

```rust
use std::sync::mpsc::{sync_channel, Receiver, RecvTimeoutError, SyncSender};
use std::thread::JoinHandle;
use std::time::{Duration, Instant};
use rusqlite::Connection;
use crate::{error::CoreError, model::{FileEntry, FolderRow, ErrRow, Hash}};

pub const BATCH_ROWS: usize = 50_000;
pub const BATCH_MS: u64 = 5_000;

pub enum Batch { /* exactly as in 4.5 */ }

impl Batch {
    fn row_count(&self) -> usize { /* len of inner Vec; 0 for control messages */ todo!() }
}

pub struct WriterHandle {
    tx: SyncSender<Batch>,
    join: JoinHandle<Result<(), CoreError>>,
}

impl WriterHandle {
    pub fn send(&self, b: Batch) -> Result<(), CoreError> {
        self.tx.send(b).map_err(|_| CoreError::WriterDied)
    }
    pub fn shutdown(self) -> Result<(), CoreError> {
        let _ = self.tx.send(Batch::Shutdown);
        self.join.join().map_err(|_| CoreError::WriterDied)?
    }
}

pub fn spawn_writer(conn: Connection) -> WriterHandle {
    let (tx, rx) = sync_channel::<Batch>(4);
    let join = std::thread::Builder::new()
        .name("db-writer".into())
        .spawn(move || run(conn, rx))
        .expect("spawn db-writer");
    WriterHandle { tx, join }
}

fn run(mut conn: Connection, rx: Receiver<Batch>) -> Result<(), CoreError> {
    let mut pending: Vec<Batch> = Vec::new();
    let mut rows = 0usize;
    let mut since = Instant::now();
    loop {
        let timeout = Duration::from_millis(BATCH_MS).saturating_sub(since.elapsed());
        match rx.recv_timeout(timeout) {
            Ok(Batch::Shutdown) => {
                commit(&mut conn, &mut pending)?;
                conn.pragma_update(None, "wal_checkpoint", "TRUNCATE")?;
                return Ok(());
            }
            Ok(Batch::Checkpoint) => {
                commit(&mut conn, &mut pending)?;
                conn.query_row("PRAGMA wal_checkpoint(PASSIVE)", [], |_| Ok(()))?;
            }
            Ok(b @ Batch::PhaseComplete { .. }) => {
                pending.push(b);
                commit(&mut conn, &mut pending)?;           // phase marker shares txn with preceding rows
                rows = 0; since = Instant::now();
            }
            Ok(b) => {
                rows += b.row_count();
                pending.push(b);
                if rows >= BATCH_ROWS { commit(&mut conn, &mut pending)?; rows = 0; since = Instant::now(); }
            }
            Err(RecvTimeoutError::Timeout) => { commit(&mut conn, &mut pending)?; rows = 0; since = Instant::now(); }
            Err(RecvTimeoutError::Disconnected) => { commit(&mut conn, &mut pending)?; return Ok(()); }
        }
    }
}

fn commit(conn: &mut Connection, pending: &mut Vec<Batch>) -> Result<(), CoreError> {
    if pending.is_empty() { return Ok(()); }
    let tx = conn.transaction()?;
    for b in pending.drain(..) { apply(&tx, b)?; }   // apply(): one match arm per Batch variant, prepared_cached stmts
    tx.commit()?;   // wal_autocheckpoint runs PASSIVE checkpoints as needed
    Ok(())
}
```

## 5. Phase 2 — Storage profile + scheduler  — 🟠 stub

**Deliverables:**
- `core/storage_profile.rs`: policy only. Detection goes through the backend `StorageProbe` trait, with `cfg`-gated code in `backend-generic/src/probe.rs`:
  - Linux: `/sys/block/<dev>/queue/rotational`.
  - Windows: `IOCTL_STORAGE_QUERY_PROPERTY` → `StorageDeviceSeekPenaltyProperty`.
  - macOS: IOKit "Solid State" medium-type property.
  - Unknown → `ssd` policy, but log it.
- `core/scheduler.rs` with `HddScheduler` and `SsdScheduler`.
- Extents: Linux `FIEMAP` (first physical extent offset) in `backend-generic`. Other OSes return `None` until Phases 3/6. Fallback sort key when there are no extents: `(file_id)`; inode order correlates with on-disk locality on ext4/XFS/NTFS.
- `pass_verify` + `--verify=byte`: byte-compare group members before `DONE` (states 3 → 4 → 5). Required later by Phase 7 actions.
- `--profile`, `--queue-depth`, `--buf-size` flags.
- HDD: merge prefix+full into one pass, sort by extent offset where available.
- SSD: parallel, high QD, passes separated.

**Acceptance** (`iostat` can't measure seek time directly, so these are throughput-based):
- Reference HDD, corpus of ≥1 MB files: aggregate hashing throughput ≥ 70% of `fio` sequential read on the same disk.
- Reference HDD, small-file corpus: extent/inode-sorted order is ≥ 2× faster than unsorted.
- Reference NVMe: throughput ≥ 80% of raw `fio` sequential read.

## 6. Phase 3 — Windows MFT backend  — ⬜ not started

**Deliverables:**
- `backend-windows/src/mft.rs` — enumeration. **Caveat:** `FSCTL_ENUM_USN_DATA` records carry FRN, parent FRN, name and attributes, but **no file size or timestamps**. Fetching those per file (`OpenFileById` + `GetFileInformationByHandleEx`) means one open per file and would erase most of the speedup. Plan: parse raw `$MFT` FILE records over the volume handle (`$STANDARD_INFORMATION` for times, unnamed `$DATA` for size, all `$FILE_NAME` attributes for hardlinks). Keep USN enumeration only as the fallback for name/parent. Spike this first (≤ 3 days) before committing to the 5–10× target.
- FRN→path reconstruction in memory during enumeration; written to DB via `folders`/`files`.
- `backend-windows/src/handle.rs` — `OpenFileById` for content reads without path.
- `backend-windows/src/overlapped.rs` — IOCP read path for SSD.
- `backend-windows/src/extents.rs` — `FSCTL_GET_RETRIEVAL_POINTERS`.
- Non-admin hint + fallback to `FindFirstFileExW(FindExInfoBasic | FIND_FIRST_EX_LARGE_FETCH)`.
- Runtime capability probe: admin? NTFS? journal active?

**Acceptance:** 1 M-file NTFS scan enumerates in < 10 s elevated (vs minutes with walk); non-admin path still correct, prints hint, completes.
